# DESIGN.md — Deeper Global Visual Design System
Version 1.0 | June 2026
This document is the authoritative design specification for deeper.global.
All UI work — whether generated by AI, written by a developer, or 
contributed by a designer — must conform to this system.
When in doubt, derive from the system. Do not invent outside it.

════════════════════════════════════════════════════════
1. DESIGN PRINCIPLES
════════════════════════════════════════════════════════

1.1 Warm authority
    The site serves people in vulnerable moments. Every visual 
    decision should feel considered, calm, and human — not clinical, 
    not corporate, not sterile. Authority comes from clarity and 
    restraint, not decoration.

1.2 Content first
    Typography and spacing exist to serve reading. No element should 
    draw attention to itself. Visual interest emerges from proportion 
    and hierarchy, not ornamentation.

1.3 Two audiences, one surface
    Every page serves a human reader and an AI/schema parser 
    simultaneously. Visual hierarchy must map cleanly to semantic 
    HTML hierarchy. Do not use visual styling as a substitute for 
    semantic structure.

1.4 Restraint over richness
    Use the minimum number of colors, weights, and sizes needed to 
    establish clear hierarchy. Adding a new color or size is a 
    system decision, not a component decision.

2. COLOR SYSTEM
════════════════════════════════════════════════════════

2.1 Token definitions

  All colors are defined as CSS custom properties in 
  src/styles/global.css. Never use hex values directly 
  in components — always reference tokens.

  NEUTRALS
  --ink:          #191716   Primary text. Body copy, headings.
  --stone:        #6b675f   Secondary text. Captions, metadata, 
                            labels, muted UI.
  --line:         rgba(25,23,22,0.12)   Subtle borders, dividers.
  --line-strong:  rgba(25,23,22,0.20)   Visible borders, separators.
  --white:        #fffdf9   Card backgrounds, elevated surfaces.
  --paper:        #f6f0e7   Page background. Warm off-white.
  --paper-deep:   #eee4d6   Recessed surfaces, callout backgrounds.

  BLUES (primary interactive / trust)
  --navy:         #0e1f33   Headings, high-emphasis text, brand.
  --deep:         #102a43   Hover states on navy elements.
  --ocean:        #1f5c8b   Primary interactive color. Links, 
                            accents, category pills, left borders.
  --ocean-bright: #2d78ad   Hover state for ocean elements.
  --mist:         #e7f0f7   Ocean-tinted backgrounds. Tags, 
                            highlighted surfaces.

  ACCENTS (warmth / humanity signals)
  --brass:        #a9823b   Hover accent. Warm highlight.
                            Used sparingly — signals engagement 
                            and warmth, never used for text.
  --clay:         #b66a4a   Warning-adjacent. Care cards, 
                            YMYL signals. Never alarming — warm.
  --clay-soft:    #f3e4dc   Clay-tinted background for care 
                            surfaces.

  SHADOW
  --shadow:       0 18px 54px rgba(14,31,51,0.14)
                            Elevated card shadow. Used on hover 
                            only — not default state.

2.2 Color pairing rules

  TEXT ON BACKGROUND
  --ink on --paper          ✅ Primary reading surface
  --ink on --white          ✅ Card body text
  --ink on --paper-deep     ✅ Callout body text
  --ink on --mist           ✅ Tag/badge body
  --stone on --paper        ✅ Secondary/metadata text
  --stone on --white        ✅ Card metadata
  --navy on --paper         ✅ Headings
  --navy on --white         ✅ Card headings
  --ocean on --paper        ✅ Links, interactive text
  --ocean on --white        ✅ Links on cards
  --ocean on --mist         ✅ Category pills
  --white on --navy         ✅ Inverted surfaces (nav)
  --white on --ocean        ✅ CTA buttons
  --clay on --paper-deep    ✅ Care card label
  --clay on --clay-soft     ✅ Care card surface
  --brass on any text       ❌ Never use brass for text
  --ocean-bright on --paper ⚠️  Hover only, not default
  Light text on --paper-deep ⚠️ Check contrast before using

  WCAG AA MINIMUMS
  Normal text (< 18px):     4.5:1 contrast ratio
  Large text (≥ 18px/bold): 3:1 contrast ratio
  UI components/borders:    3:1 contrast ratio

  Verified passing combinations:
  --ink / --paper:          16.2:1  ✅
  --ink / --white:          17.1:1  ✅
  --navy / --paper:         13.4:1  ✅
  --ocean / --white:        4.6:1   ✅
  --ocean / --mist:         3.8:1   ✅ (large text only)
  --stone / --paper:        5.9:1   ✅
  --clay / --clay-soft:     3.2:1   ✅ (large text / UI only)

2.3 Accent usage rules

  --ocean:        Primary accent. Links, active states, 
                  left-border on cards, category pills.
                  Maximum 2 ocean elements visible 
                  simultaneously in any viewport region.

  --brass:        Hover accent only. Never default state.
                  Used on card left-border on hover, 
                  bullet markers in key-takeaways,
                  and pull-quote decorations.
                  Never on text. Never on backgrounds 
                  larger than a 3px border.

  --clay:         Care and YMYL surfaces only.
                  Left-border on care card.
                  Sidebar label for care card.
                  Crisis-adjacent UI elements.
                  Never used to signal error or danger —
                  always warm, never alarming.

3. TYPOGRAPHY SYSTEM
════════════════════════════════════════════════════════

3.1 Typefaces

  DISPLAY / HEADINGS
  Font:     Cormorant Garamond
  Weights:  400 (regular), 400i (italic), 600 (semibold)
  Role:     All headings h1–h4, pull quotes, 
            section titles, brand wordmark.
  Character: Warm, authoritative, editorial. 
              Signals depth and care without coldness.

  BODY / UI
  Font:     Jost
  Weights:  400 (regular), 500 (medium), 600 (semibold)
  Role:     Body copy, UI labels, navigation, pills, 
            captions, metadata, buttons.
  Character: Geometric sans. Clean, readable, modern.
              Pairs with Cormorant without competing.

  FALLBACK STACK
  Headings: 'Cormorant Garamond', Georgia, 'Times New Roman', serif
  Body/UI:  'Jost', ui-sans-serif, system-ui, -apple-system,
             BlinkMacSystemFont, 'Segoe UI', sans-serif

  LOADING
  Both fonts loaded via Google Fonts in BaseLayout.astro.
  Use display=swap. Preconnect to fonts.googleapis.com 
  and fonts.gstatic.com.

3.2 Type scale

  Based on Major Third ratio (1.250).
  Base: 16px (1rem).

  TOKEN         SIZE      REM     USE
  --text-xs     12px      0.75    Labels, timestamps, legal
  --text-sm     14px      0.875   Captions, metadata, citations
  --text-base   16px      1.000   Body copy (default)
  --text-md     18px      1.125   Answer lede, large body
  --text-lg     20px      1.250   Small headings, card titles
  --text-xl     24px      1.500   h3, sidebar entity names
  --text-2xl    30px      1.875   h2, section headings
  --text-3xl    38px      2.375   h1 (answer page)
  --text-4xl    48px      3.000   h1 (hero / index)

  Add to :root in global.css:
  --text-xs:   0.75rem;
  --text-sm:   0.875rem;
  --text-base: 1rem;
  --text-md:   1.125rem;
  --text-lg:   1.25rem;
  --text-xl:   1.5rem;
  --text-2xl:  1.875rem;
  --text-3xl:  2.375rem;
  --text-4xl:  3rem;

3.3 Line height

  TOKEN               VALUE   USE
  --leading-tight     1.2     Display headings, h1
  --leading-snug      1.3     Card titles, h2, h3
  --leading-normal    1.5     UI elements, labels
  --leading-relaxed   1.65    Body copy, summaries
  --leading-loose     1.8     Long-form answer body

  Add to :root:
  --leading-tight:    1.2;
  --leading-snug:     1.3;
  --leading-normal:   1.5;
  --leading-relaxed:  1.65;
  --leading-loose:    1.8;

3.4 Measure (line length)

  Optimal reading measure by text role:

  Answer body (long-form):    62–68 characters (~38rem)
  Lede / summary:             55–65 characters (~36rem)
  Card summary:               50–60 characters (~34rem)
  Sidebar text:               38–46 characters (~24rem)
  Labels / pills:             No constraint (short by nature)

  Enforce via max-width on text containers, not on layout 
  columns. The layout column may be wider than the measure.

3.5 Heading hierarchy rules

  h1    One per page. Page title only.
        Cormorant Garamond, --text-3xl (answer pages) 
        or --text-4xl (index/hero).
        Weight 600. Color --navy. Leading --leading-tight.

  h2    Section titles within answer body.
        Cormorant Garamond, --text-2xl.
        Weight 600. Color --navy. Leading --leading-snug.
        Margin-top: --space-2xl. Margin-bottom: --space-sm.

  h3    Subsection or sidebar section titles.
        Cormorant Garamond, --text-xl.
        Weight 600. Color --navy. Leading --leading-snug.

  h4    Rarely used. Definition terms, tight callout titles.
        Jost, --text-base. Weight 600. 
        Uppercase. Letter-spacing 0.06em. Color --stone.

  SIDEBAR LABELS (not headings — use <p class="sidebar-label">)
        Jost, --text-xs. Weight 600.
        Uppercase. Letter-spacing 0.08em. Color --stone.
        These are not semantic headings. Do not use h tags.

3.6 Body text rules

  Default body:
    Font: Jost 400
    Size: --text-base (1rem)
    Line-height: --leading-relaxed (1.65)
    Color: --ink
    Max-width: 38rem on answer body columns

  Answer lede / summary:
    Font: Jost 400
    Size: --text-md (1.125rem)
    Line-height: --leading-loose (1.8)
    Color: --ink
    Font-style: normal (never italic)
    Max-width: 36rem

  Metadata / captions:
    Font: Jost 400
    Size: --text-sm (0.875rem)
    Line-height: --leading-normal (1.5)
    Color: --stone

  Citation / legal:
    Font: Jost 400
    Size: --text-xs (0.75rem)
    Line-height: --leading-normal (1.5)
    Color: --stone

4. SPACING SYSTEM
════════════════════════════════════════════════════════

4.1 Base unit

  4px (0.25rem). All spacing is a multiple of 4px.
  Never use arbitrary values like 13px, 22px, or 1.3rem.
  If a value isn't in the scale, use the nearest token.

4.2 Spacing scale

  TOKEN         SIZE    REM     USE
  --space-1     4px     0.25    Icon gaps, tight inline
  --space-2     8px     0.5     Pill padding (vertical)
  --space-3     12px    0.75    Tight element gaps
  --space-4     16px    1.0     Default element padding
  --space-5     20px    1.25    Card internal gap
  --space-6     24px    1.5     Section element spacing
  --space-8     32px    2.0     Card padding
  --space-10    40px    2.5     Between components
  --space-12    48px    3.0     Section top padding
  --space-16    64px    4.0     Major section breaks
  --space-20    80px    5.0     Hero / page-level spacing
  --space-24    96px    6.0     Maximum section padding

  Add to :root:
  --space-1:  0.25rem;
  --space-2:  0.5rem;
  --space-3:  0.75rem;
  --space-4:  1rem;
  --space-5:  1.25rem;
  --space-6:  1.5rem;
  --space-8:  2rem;
  --space-10: 2.5rem;
  --space-12: 3rem;
  --space-16: 4rem;
  --space-20: 5rem;
  --space-24: 6rem;

4.3 Component spacing rules

  Card internal padding:      --space-8 (32px) sides
                              --space-6 (24px) top/bottom
  Card gap in grid:           --space-6 (24px)
  Section padding (vertical): --space-16 (64px) default
                              --space-20 (80px) hero sections
  Sidebar card gap:           --space-5 (20px)
  Heading to body gap:        --space-4 (16px)
  Paragraph gap:              --space-5 (20px) (via margin-bottom)
  List item gap:              --space-3 (12px)
  Pill padding:               --space-2 (8px) vertical
                              --space-3 (12px) horizontal
  Breadcrumb item gap:        --space-2 (8px)

6. LAYOUT SYSTEM
════════════════════════════════════════════════════════

6.1 Container

  Max-width:  --max (1120px), defined in :root
  Padding:    0 --space-6 (24px) on mobile
              0 --space-8 (32px) on tablet+
  Margin:     0 auto

6.2 Answer page layout

  Two-column grid above 768px:
    Main column:    minmax(0, 1fr)  (~65% at max-width)
    Sidebar:        320px fixed
    Gap:            --space-10 (40px)

  Below 768px: single column, sidebar stacks below main.

6.3 Answer card grid

  Results page:     single column list (not grid)
                    max-width 760px, centered
                    gap: --space-4 between cards

  Related questions: 2-column grid above 640px
                     1-column below
                     gap: --space-5

7. INTERACTION STATES
════════════════════════════════════════════════════════

7.1 Transitions

  All interactive transitions: ease timing function
  Duration:   0.15s for color/opacity changes
              0.2s for shadow/transform changes
  Never use linear. Never exceed 0.3s for UI feedback.

7.2 Focus states

  All interactive elements must have visible focus ring.
  Use:  outline: 2px solid var(--ocean)
        outline-offset: 3px
  Never remove focus outline without replacing it.

7.3 Hover states

  Links:      color shift to --ocean-bright or --ocean
              underline appears (if not already present)
  Cards:      box-shadow var(--shadow) appears
              border-left shifts to --brass
  Pills:      background shifts, border appears
  Buttons:    background darkens by one token step

9. USAGE IN CURSOR SESSIONS
════════════════════════════════════════════════════════

When beginning any UI task in Cursor, include this 
instruction at the top of your prompt:

  "Read DESIGN.md in the repo root before making any 
  changes. All sizing, spacing, color, and typography 
  decisions must use tokens and rules defined there. 
  Do not introduce values outside the system."

When adding a new component:
  1. Identify which existing component spec is closest
  2. Derive from it using system tokens
  3. Document any new patterns here before shipping

When deviating from this spec is necessary:
  1. Note the deviation and reason in a code comment
  2. Propose the addition to DESIGN.md rather than 
     leaving it undocumented in a component
